| 项目 | 内容 |
|---|---|
| 产品 | 抖音划走（Android） |
| 当前版本 | v0.8 |
| 更新日期 | 2026-11-19 |
| 状态 | 自用版本已可用，规则持续调优中 |

## 一、背景

刷抖音推荐流时，广告、直播带货、挂购物链接、团购推广这几类视频出现得很频繁。每条单独划走只要一秒，但它们打断了观看节奏，累积起来让人觉得“手机很吵”。

抖音的广告和正常视频走同一套接口、用同一种卡片下发，没法像网页那样在网络层拦截。手机上唯一可行的办法，是在画面层面认出这类视频，然后替用户划走。

现有工具覆盖不到这个场景。李跳跳、GKD 这类无障碍工具主要处理开屏广告和双列卡片流，对抖音竖屏视频流里的广告、带货、直播基本没有规则。

## 二、目标与衡量

**产品目标**：刷抖音推荐流时，命中规则的商业化视频在用户反应过来之前就被划走，全程不需要用户操作，也不影响正常视频。

| 指标 | 定义 | 目标值 |
|---|---|---|
| 识别耗时 | 新视频出现到判定完成的时间 | 快速查找 < 50ms，兜底遍历 < 200ms |
| 漏划率 | 应划未划的条数 ÷ 应划总条数（以“漏了，记一下”的记录为样本） | < 10% |
| 误划率 | 被划走的正常视频 ÷ 被划走总数（试运行期间人工判断） | < 3% |
| 存活率 | 一天内服务不被系统杀掉、无需手动重开的天数占比 | > 95% |
| 耗电 | 刷抖音 1 小时，本应用的额外耗电 | < 2% |

## 三、用户与场景

**目标用户**：每天刷抖音推荐流、对广告和带货反感、用的是安卓手机（首先是小米/HyperOS）的人。

| 场景 | 用户行为 | 期望结果 |
|---|---|---|
| 日常刷推荐流 | 上下滑看视频 | 广告、直播、带货、团购视频被自动跳过 |
| 想看某条带货视频 | 临时不想被划走 | 下拉控制中心一键暂停，看完再打开 |
| 发现有漏网的 | 刷到没被划走的广告 | 在通知栏点一下记录下来，用来补规则 |
| 第一次安装 | 打开 App | 按引导两步完成授权，不需要自己去设置里找 |

## 四、范围

| 类别 | 内容 |
|---|---|
| 本期做 | 抖音竖屏推荐流；广告、直播带货、购物链接、团购、软广五类规则；暂停开关；漏划记录；小米机型的授权和保活引导 |
| 本期不做 | 小红书、快手、视频号等其他平台；iOS（系统不开放读取其他 App 界面和模拟滑动）；联网下发规则；大模型判断软广 |
| 不会做 | Root、Hook、修改抖音安装包等侵入式方案（有封号和安全风险） |

## 五、功能需求

### 5.1 视频识别与自动划走

切到新视频时，读取当前屏幕上的文字，命中任意一类已开启的规则就自动上滑一次。

| 项目 | 规则 |
|---|---|
| 生效范围 | 只在抖音（com.ss.android.ugc.aweme）处于前台时工作，其他 App 一律不处理 |
| 触发时机 | 抖音界面有变化就检查，两次检查最少间隔 150ms；划走后静默 800ms，等下一条视频加载完 |
| 识别方式 | 先按关键词让系统直接查找（快）；没命中时把整个界面读一遍再匹配（准），兜底最多每 400ms 一次 |
| 有效区域 | 只看屏幕可见区域；顶部 12% 的标签栏（推荐、团购、商城等）不参与识别 |
| 不划的情况 | 评论区或输入框打开时不划，避免把评论列表划走；暂停状态下不划 |
| 划走动作 | 从屏幕 72% 高度滑到 22% 高度，用时 150ms，和手动上滑一样 |

### 5.2 识别规则

五类规则各自独立开关，关键词可改。长度上限用来区分“标签”和“正文”：比如“广告”只认 8 个字以内的短文本，避免把标题里提到“广告”二字的正常视频误划。

| 规则 | 默认 | 默认关键词 | 匹配长度上限 |
|---|---|---|---|
| 广告 | 开 | 广告、赞助 | 8 字 |
| 直播带货 | 开 | 直播中、点击进入直播间、进入直播间、查看直播 | 30 字 |
| 购物链接 | 开 | 购物车、小黄车、商品橱窗、立即购买、去购买、去抢购、已售、券后 | 30 字 |
| 团购 | 开 | 团购、限时秒杀、免预约、到店、门店 | 30 字 |
| 软广 | 开 | 种草、好物推荐、好物分享、同款链接、旗舰店、左下角 | 不限，只看屏幕下方 60% 的标题区 |

关键词编辑：点规则所在行弹出编辑框，用逗号分隔，可以一键恢复默认。英文不区分大小写。用户自己加品牌名（比如“Aspen Sport”），就能划走该品牌的软广。

### 5.3 试运行

新装或改规则后，用户需要先确认不会误划。

| 项目 | 规则 |
|---|---|
| 行为 | 命中时不划走，只弹出提示“会划走：xxx”，xxx 是命中的文字 |
| 默认 | 首次安装默认开启 |
| 计数 | 试运行命中也计入“已划走”数字 |

### 5.4 暂停与继续

用户临时想看某条带货或直播视频时，可以暂停，不用去系统设置里关服务。

| 入口 | 交互 |
|---|---|
| App 首页 | 点右上角状态按钮切换；暂停时顶部从黄色变灰，按钮显示“暂停了” |
| 常驻通知 | 通知上的“暂停 / 继续”按钮 |
| 控制中心 | “抖音划走”快捷开关，开启显示“开着”，暂停显示“暂停了” |

三个入口的状态实时同步。暂停只是停止识别和划走，服务和计数都保留。

### 5.5 漏划记录

规则靠真实样本才能写准，需要一个低成本收集样本的方式。

| 项目 | 规则 |
|---|---|
| 入口 | 常驻通知上的“漏了，记一下” |
| 行为 | 收起通知栏，等 450ms 后读取抖音当前画面上的全部文字和位置，追加保存到本地文件 |
| 存储 | Android/data/com.lbr.skipad/files/missed.txt，超过 2MB 自动清空重写 |
| 查看 | App 首页“漏划记录”，显示已记录条数，可以分享最近一条 |
| 调试模式 | 默认关；开启后每条视频的界面文字都会记下来，会变慢，排查完要关掉 |

### 5.6 开启引导

在小米手机上，从未知来源安装的 App 默认不能申请无障碍权限（会显示“由受限设置控制”），必须先放开权限，再打开无障碍。

| 步骤 | 跳转 | 跳转失败时 |
|---|---|---|
| 1. 允许获取权限 | 小米“权限管理”页，用户点右上角 ⋮ → 允许应用获取权限 | 退回系统“应用信息”页 |
| 2. 打开无障碍 | 尝试直达本应用的无障碍开关页 | 退回“无障碍”总页面，用户点“已下载的应用”找到「抖音划走」 |

服务开启后回到 App，引导弹窗自动关闭。

### 5.7 后台保活

小米系统会冻结、清理没有常驻通知的后台应用，导致服务不工作。

| 措施 | 做法 |
|---|---|
| 常驻通知 | 服务运行时显示最低优先级的常驻通知，内容是状态和“划走了 N 条” |
| 用户引导 | 首页“后台保活”弹窗列出三步：省电策略设为无限制、打开自启动、在最近任务里锁住，可以一键跳到应用信息页 |

## 六、界面设计

设计原则：只放名词和开关，不放说明文字；一个明黄色块撑起首页，其余全部留白。

| 区域 | 内容 |
|---|---|
| 顶部黄色区 | 应用名；超大黑色数字显示累计划走条数；右下角状态按钮（开着 / 试运行 / 暂停了 / 点这里开启） |
| 规则列表 | 五行，每行只有规则名和开关，点行名编辑关键词 |
| 试运行 | 一行开关 |
| 二级入口 | 后台保活、漏划记录，点开是弹窗 |

| 元素 | 规格 |
|---|---|
| 主色 | 明黄 #FFD60A，黑 #000000，白底 |
| 暂停态 | 顶部变浅灰 #E5E5EA，数字变灰 #8E8E93 |
| 开关 | 打开为黑色轨道配黄色圆点，关闭为浅灰 |
| 图标 | 黄底上两个粗黑向上箭头，意思是“往上划走”；通知栏和控制中心用同款单色图标 |
| 文案 | 口语短句，例如“开着”“划走了 N 条”“漏了，记一下”“会划走：直播中” |

## 七、非功能需求

| 类别 | 要求 |
|---|---|
| 隐私 | 不申请联网权限，所有数据只存在本机；只读取抖音的界面，不读其他 App |
| 性能 | 平时只做快速查找；完整读一遍界面限频 400ms；调试模式默认关闭 |
| 兼容 | 最低 Android 8.0（API 26），targetSdk 33；主要适配小米 HyperOS |
| 安装包 | 小于 50KB，不依赖第三方库 |
| 升级 | 固定签名密钥，后续版本都可以覆盖安装，保留设置和计数 |

## 八、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 抖音改版后界面文字变了 | 某类规则失效，漏划变多 | 关键词可以在 App 里直接改；用漏划记录快速找到新文字 |
| 抖音把标签改成图片或做混淆 | 读不到文字，规则全部失效 | 备选方案：截屏后识别文字，代价是耗电和延迟上升 |
| 宽泛关键词误划（种草、已售、到店等） | 正常视频被划走 | 先用试运行观察；误划多的词从默认列表里拿掉 |
| 系统杀后台 | 服务不工作，用户以为功能坏了 | 常驻通知 + 保活引导；通知消失即说明服务被杀 |
| 抖音检测无障碍自动操作 | 账号被限制的可能性很低，但不为零 | 只做和手动一样的上滑，不点击、不批量操作 |
